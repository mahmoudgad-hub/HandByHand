## البوابة

شريط الهاتف: الرئيسية /home، المواعيد /schedule، متابعة طفلي /progress، البرنامج المنزلي /activities، حسابي /profile. قائمة «المزيد» ثابتة للفواتير /billing والطلبات /requests والإشعارات /notifications وتغيير الطفل /welcome. المزيد MODAL دون route إضافي.

/progress يحتوي progress/reports/notes؛ التقرير المفرد /reports/:reportId يبقى. /requests يحتوي requests/messages؛ رسائل الأسرة بلا اشتراط اختيار طفل، وإرسال/عرض طلب الطفل يتطلب ChildContext. الدخول للاستشارة بالموعد دون childSelectedGuard كما هو. لا تضف Assessment route بلا API ولا Payments page منفصلة عن billing لمجرد ورودها في المثال.

## ملكية البيانات

الطلب يحتفظ ببيانات التقديم، ويرتبط بملف الطفل والأسرة بعد التحويل. ملف الطفل مركز التشغيل/السريري، والأسرة تجمع الأبناء والماليات. عرض نفس الفاتورة من الأسرة والطفل ليس duplication لوحدة أعمال عندما يستعمل نفس القراءة والمكون والفعل.

### ١.٢ · ما يخرج من القائمة (لا من النظام)

| البند الحالي | مصيره |
|---|---|
| صندوق الوارد | يصير «الإشعارات» |
| يومي | عرض «مواعيدي» داخل المواعيد (`/my-day` → `/appointments?view=mine`) |
| خدمات الأخصائيين | تبويب في الأخصائيين (`/therapist-services` → `/therapists?tab=services`) |
| فريق العمل | تبويب في الموقع التعريفي (`/site/team` → `/site?tab=team`) |
| الصلاحيات والشاشات | «المستخدمون والأدوار» (`/access` → `/users`) |
| الأطفال | «المستفيدون» + «أولياء الأمور» |

### ١.٣ · قواعد المسارات المستهدفة

- المسارات القديمة **تبقى تعمل** بإعادة توجيه (Deep Links في الإشعارات والرسائل والبريد): `/inbox`, `/my-day`, `/therapist-services`, `/site/team`, `/access`, `/children` (يبقى كما هو).
- الحالة **دائمًا** `?status=`؛ العرض `?view=`؛ التبويب `?tab=`. لا مسار جديد لحالة.
- التفصيل: `/enrolments/:id`, `/guardians/:id`, `/children/:id`. الموعد والفاتورة **درج جانبي** على شاشتهما (`?open=`) لا مسار — كيانان قصيرا العمر يُخدمان في سياق يومهما.
- الحارس يسمّي **صلاحية القاعدة نفسها** (R-10).
