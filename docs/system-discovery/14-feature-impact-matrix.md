## أمثلة أثرٍ محسوبة

### مثال ١ — «أريد أن يحجز وليّ الأمر بنفسه» (`BL-03`)

| الطبقة | الأثر |
|---|---|
| Frontend | شاشة حجز جديدة في البوّابة · وشاشة `/requests` **يسقط نصف معناها** |
| Backend | `POST /appointments` يحتاج مسارًا للبوّابة بصلاحية مختلفة |
| Database | `APPOINTMENT.BOOK` لدور `GUARDIAN`؟ **أم دالّة جديدة بقواعدها؟** · وسياسة `appointments` للكتابة |
| Status | لا حالة جديدة |
| Notification | `APPOINTMENT_BOOKED` يذهب للأسرة **ولمن في المركز؟** (`STAFF_APPOINTMENT_BOOKED` موجود) |
| Security | 🔴🔴 **أوّل كتابة على الجدول السريري من البوّابة** — والحدّ الحالي أن وليّ الأمر يكتب في موضعين فقط (`activity_log` · `parent_requests`) |
| **التأثير الجانبي المكتوب** | **`parent_requests` بأنواعها الثلاثة هي البديل المصمَّم — فإن حجز الأب، سقط نصفها** |
| Tests | `p3` · `p5` · `a3` · `a5` · `a10` · `e2` |

### مثال ٢ — «أريد جلسات جماعية» (`BL-27`)

| الطبقة | الأثر |
|---|---|
| Database | 🔴🔴 **قيد الاستبعاد على الطفل — والجماعية تحتاج عكسه.** وجدول مشاركين لا وجود له، **وقرار «طفل واحد لكل جلسة» مقفول** |
| كل شيء بعده | `caseload` · `start_session` · الفاتورة · البثّ (كاميرا واحدة وطفلان؟) · سلّم الرؤية (وليّ أمر يرى ملاحظةً فيها طفل غيره؟) |
| **الحكم** | **ليست تعديلًا بل نقضًا لقرار مقفول** — يمرّ بالمالك أوّلًا |

### مثال ٣ — «أريد ربط الجلسة بخصم الباقة» (C-01)

| الطبقة | الأثر |
|---|---|
| Frontend | لا شيء · **إلّا إن كان الرفض يجب أن يظهر** |
| Backend | لا شيء إن كان الخصم في القاعدة (القاعدة ٢) |
| Database | `close_session` تنادي `consume_package_session` — **وفي جملة مستقلّة** (`27000`) · و`HB051` يصير رفضًا حقيقيًّا |
| Status | `child_packages.EXHAUSTED` تصير قابلة للوصول |
| Notification | **هل تُشعَر الأسرة عند نهاية الرصيد؟** لا نوع موجود |
| Security | 🟡 |
| **السؤال العالق** | **هل جلسةٌ بلا رصيد تُرفض أم تُخصَم سلبًا أم تُحتسب فاتورةً؟** — `OQ-02` · `BL-37 (ج)` |
| Tests | `p6` · `p3` · `a3` · `a5` |

### مثال ٤ — «أسرة دولية تدخل البوّابة» (C-05)

| الطبقة | الأثر |
|---|---|
| Database | ✅ **جاهزة ومقبولة** — `p15` مجموعة قبول كاملة على `0112`–`0114` |
| Backend | ✅ جاهز |
| Frontend | 🔴 **`phonePattern: '^01[0-9]{9}$'` في `web/shared/src/config/app-config.ts:95`** + `/^01[0-9]{9}$/` **مكتوبًا حرفيًّا مرّتين** في `apply.ts` |
| **الحكم** | **الميزة مقبولة في القاعدة ومحجوبة في النموذج** — وأوّل أسرة دولية تُرفَض عند الكتابة، بلا أي رسالة تشرح السبب الحقيقي |
| Tests | `p15` خضراء · ولا فحص واجهة يقابلها |

## كيف يُقرأ هذا الجدول قبل أي تطوير

1. اقرأ صفّ الميزة المستهدفة → أعمدة الطبقات تقول **أين تكتب**.
2. اقرأ `Used By` في [13](13-feature-dependency-map.md) → تقول **ما قد ينكسر**.
3. اقرأ عمود `Tests` → **تلك هي مجموعات الانحدار الإلزامية**.
4. وإن كان عمود Security 🔴🔴 أو أعلى: **الفحص يسبق الكتابة، ويسبقه `SET ROLE
   hbh_app`** — لأن فحصًا يعمل بدور المالك يثبت أن المالك يمرّ.
