# Hand By Hand — الجهات والمسؤوليات

تاريخ المراجعة: 2026-09-14. المرحلة: Analysis + Journey Mapping + UX Audit فقط. لا يتضمن هذا التسليم تغييرًا في التطبيق أو قاعدة البيانات.

## حدود الدليل

**حدود اللقطة أثناء التسليم:** أظهر فحص SHA-256 تغير 18 ملفًا وإضافة ملف مصدر واحد بالتزامن مع كتابة التقرير، خارج تعديلات هذه المهمة، ضمن الموقع وبعض واجهات الموظفين والبوابة. بقيت الملفات المقروءة في API وDB مطابقة للبصمة المرجعية. راجعنا تغيير محرر المراجع وصححنا JG-22: أصبحت المراجع المعرّفة تدعم الاختيار بالأسماء. لا تمثل هذه الحزمة لقطة Git مجمدة؛ يلزم إعادة تحقق الواجهات المتغيرة عند تثبيت نسخة الإطلاق. تعديلات هذه المهمة نفسها مقتصرة على ملفات التدقيق الثلاثة عشر.

هذه مراجعة للنسخة المحلية الحالية، بما فيها التعديلات غير الملتزمة في Git، وليست مراجعة HEAD وحده. جرى فحص routes والقوالب وإجراءات TypeScript وعقود Go ودوال SQL والهجرات والبذور، والاستعانة بالوثائق السابقة كفهرس ثم التحقق من المصدر. وجود هجرة على القرص لا يثبت تطبيقها على قاعدة الإنتاج. ملفات `db/held/` تصميم معلّق، ولا تدخل في وصف السلوك الحالي.

محاولة معاينة `localhost:4200/apply` وصلت إلى مشروع آخر اسمه MyLinks؛ استُبعد تمامًا. `localhost:8091/apply`، وهو منفذ البوابة الموثق في إعداد النشر، رفض الاتصال. محاولة متابعة واجهة الموظفين تعثرت في أداة المتصفح قبل معاينة صالحة. لم يُجرَ تسجيل دخول أو تغيير سجلات أو دفع أو إرسال رسائل. لم تتوفر مشاهدة موثوقة للشاشات المصادق عليها أو اختبار جهاز موبايل. لذلك «موجود» أدناه يعني موصولًا في المصدر، ولا يعني نجاح تجربة إنتاج حية.

المواعيد والحالات مأخوذة من SQL الحالي، مع تتبع التعريفات اللاحقة. أمكن قراءة ملفي 0005 و0006 بعد توسيع صلاحية القراءة فقط. لا حاجة لتغيير ملفات الملكية أو الوثائق القديمة؛ هذه حزمة جديدة طلبها المالك صراحة.

## قاموس التقييم

| التصنيف | المقصود |
|---|---|
| موصول | شاشة ← إجراء ← API ← تنفيذ/قراءة في DB مثبتة من المصدر |
| جزئي | جزء موصول لكن تسليم المسؤولية أو رجوع النتيجة مفقود |
| DB فقط | بنية/دالة موجودة ولا مسار واجهة متصل بها |
| UX GAP | خطوة عمل بلا شاشة أو CTA قابل للتنفيذ، أو نتيجة لا توضح التالي |
| Operational Gap | تنفيذ يعتمد على ذاكرة الموظف أو اتصال خارج النظام بلا متابعة موثقة |
| مستهدف | اقتراح في هذه الحزمة، لا ادعاء بأنه موجود |
| يحتاج تحقق حي | الأداء والتوقيت والتخطيط المرئي والصلاحيات الفعلية وتسليم الرسائل |

## الجهات الحقيقية

| Actor | Role code الحالي | ما يراه / يفعله | ما ليس مفصولًا حاليًا | التسليم المتوقع |
|---|---|---|---|---|
| ولي الأمر | GUARDIAN | OTP، اختيار طفل، المواعيد والتقدم والتقارير والأنشطة والفواتير والرسائل | لا إنشاء حجز ذاتي أو رفع إيصال أو استكمال شامل للملف | طلب مفهوم ثم نتيجة تخص الطفل الصحيح |
| الاستقبال | RECEPTION | المهام، الأسر والأطفال، الالتحاق، حجز/تأكيد/حضور/إلغاء، طلبات الأسر، قراءة مالية | لا BILLING.MANAGE افتراضيًا؛ شراء باقة أو إثبات تحصيل ليسا من صلاحياته الافتراضية | يسلّم الجلسة للأخصائي والقرار المالي للمخول |
| مدير المركز | CENTER_ADMIN | صلاحيات الإدارة والحجز والمال والتقارير والكتالوج والمستخدمين | المدير وAdmin ليسا دورين مستقلين في البذور | يقرر الإسناد والاعتماد والتصعيد، مع سبب وسجل |
| الأخصائي | THERAPIST | يومه، بدء وإغلاق جلساته، الملاحظات، التقارير، الخطط والأهداف والقياسات | لا تخصيص مستقل لموافقة المدير؛ PLAN.MANAGE مشترك | توثيق النتيجة ونشر ما ينبغي للأسرة |
| الإدارة التقنية | CENTER_ADMIN حاليًا | المستخدمون والأدوار والإعدادات والسجلات ومحتوى الموقع | اختلاط التشغيل اليومي بإدارة الصلاحيات | إصلاح سبب التعطل وإعادة المهمة لصاحبها |
| الحسابات / مراجع الدفع | لا role مستقل في seed | من يحمل BILLING.MANAGE يستطيع إصدار الفواتير وتسجيل المدفوعات وبيع الباقات | لا receipt review queue ولا صلاحية مستقلة لمراجع الإيصالات | لا يجوز مساواة موظف الاستقبال تلقائيًا بمراجع دفع |
| System | API + PostgreSQL + maintenance + SMS + meeting provider | التحقق، RLS، الحالات، التدقيق، الإشعار، انتهاء الصلاحيات | إنشاء إشعار في DB لا يثبت وصول SMS؛ provider readiness يحتاج تحققًا | يعيد نتيجة قابلة للفهم مع مالك الخطوة التالية |

المصدر: [بذور الأدوار والصلاحيات](../../db/seed/0002_rbac.sql)، [حراس ومسارات الموظفين](../../web/ops/src/app/app.routes.ts)، [حراس البوابة](../../web/portal/src/app/core/auth/auth.guard.ts). الأدوار قابلة للإدارة عبر `/users`؛ توزيع الحسابات الحي قد يختلف عن البذور.

## مصفوفة العمل والفصل بين القرار والتنفيذ

| خطوة | ينفذ الآن | المسؤول المستهدف | الدليل / الفجوة |
|---|---|---|---|
| استقبال طلب جديد | ENROLMENT.MANAGE | الاستقبال يسجل، المدير يراجع الملاءمة | لا حالة مراجعة مدير منفصلة؛ JG-01/JG-11 |
| تعيين أخصائي تقييم قبل التحويل | غير موصول على الطلب | المدير | صفحة الطلب تعرض عدم الإسناد؛ JG-02 |
| ضبط موعد التقييم | تغيير حالة لا يحمل التاريخ المطلوب | الاستقبال بعد قرار المدير | JG-02 |
| كتابة ونشر التقييم | DB فقط | الأخصائي ثم من يملك الاعتماد المطلوب | JG-03 |
| اقتراح واعتماد خطة | إنشاء DRAFT متاح؛ التفعيل غير موصول | الأخصائي يقترح، المدير يعتمد | JG-04 |
| تسجيل حضور | APPOINTMENT.BOOK | الاستقبال | لا يساوي بدء الجلسة |
| بدء/إغلاق جلسة | SESSION.START / SESSION.COMPLETE | الأخصائي؛ الصلاحية تحدد الاستثناءات | الكاتب السريري حق منفصل عن إغلاق الجلسة |
| نشر ملاحظة للأسرة | NOTE.PUBLISH | الأخصائي | INTERNAL لا يصل للأسرة |
| نشر تقرير رسمي | REPORT.PUBLISH | الأخصائي/المدير بحسب الصلاحيات الحالية | نشر صريح، ليس أثر إغلاق الجلسة |
| تسجيل تحصيل | BILLING.MANAGE | الحسابات أو المدير المفوض | ليس موافقة على إيصال مرفوع |
| قرار إعادة جدولة | REQUEST.MANAGE | الاستقبال | القرار لا ينفذ تعديل الموعد؛ JG-10 |
| مراجعة التقدم | قياسات متاحة، قرار مراجعة غير موصول | الأخصائي + المدير + الأسرة | JG-26 |

## الـDashboard المناسب لكل دور

| الدور | السؤال الأول | ما يوجد الآن | ما يحتاج استكمالًا |
|---|---|---|---|
| Parent | ماذا يحتاج طفلي بعد ذلك؟ | الموعد القادم، آخر متابعة، نشاط اليوم، مستحقات | الطلب قبل التحويل، موعد صدور التقرير، استلام الدفع، سبب عدم وجود موعد |
| Reception | ما الذي يحتاج مني اليوم؟ | `/tasks` وتأكيد/حضور/طلبات وملخص يوم | مالك شخصي، موعد تنفيذ الطلب المقبول، استثناءات الأمس |
| Manager | ما الذي ينتظر قراري؟ | مؤشرات قابلة للفتح ومهام حسب permissions | اعتماد تقييم/خطة ومراجعة إيصال غير موجودة، فلا يجوز أن يبدو الصفر «لا قرارات» |
| Specialist | من عندي وماذا أنهي بعد الجلسة؟ | لوحة «يومك» وبدء الجلسة ومهام مسودات | كشف جلسة بلا توثيق، التقييمات، مراجعات الخطط، تناقض نص اليوم JG-21 |
| Finance/Admin | ما الذي يمنع التأكيد أو الاستحقاق؟ | فواتير ومدفوعات وأرصدة | إيصالات وقسط/اشتراك قابل للمتابعة من المصدر المالي نفسه |

المهام الحالية مشتقة عند القراءة، وليست سجل عمل مسندًا له owner وSLA وإقرار استلام. `assignedRole` في نموذجها يحمل permission في مواضع كثيرة، لا موظفًا مكلفًا. لا تُعتبر مشاهدة البطاقة استلامًا للمسؤولية.
