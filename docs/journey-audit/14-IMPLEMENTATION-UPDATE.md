# تنفيذ إصلاحات على النسخة الحالية — 2026-09-14

بعد موافقة المالك على التعديل، نُفذت الإصلاحات التالية في مساحة العمل الحالية مع الحفاظ على التغييرات الموجودة. هذا تحديث لنتائج التدقيق، وليس إعلان إغلاق جميع الفجوات أو نشر نسخة إنتاج.

| الفجوة | ما تغير | الحدود المتبقية |
|---|---|---|
| JG-02 — موعد التقييم | نموذج الحالة يطلب الموعد عند اختيار ASSESSMENT_BOOKED فقط؛ يحوله من توقيت المركز إلى UTC ويرسله إلى API. الخادم يكتب assessment_at مع الحالة في نفس UPDATE ويعيده في القراءة. تفاصيل الطلب تعرض الموعد، والخطوة التالية بعد التواصل تفتح تسجيله. | موعد مقابلة على الطلب؛ لا ينشئ حجز أخصائي/غرفة ولا يسجل نتيجة تقييم. قيود DB وآلة الحالة القائمة تظل المرجع. |
| JG-14 — سياق الإشعارات | يجلب الأسرة المصرح بها قبل فتح إشعار مرتبط بطفل، ويختار الطفل بالمعرف قبل التنقل. لا يفتح سياق أخيه عند غياب الوصول أو فشل الشبكة. إشعار الملاحظة يفتح progress مع tab=notes. | التركيز على فاتورة/موعد بعينه داخل القوائم ودورة إشعار التقييم لم يكملا. |
| JG-13 — الموافقات | إزالة المفاتيح التي كانت ترفض كل محاولة حفظ. عرض السماح بالبث المقروء من الخادم لكل طفل، وإزالة حالتي SMS والصور اللتين كانتا تُختلقان بقيمة false. رابط إلى مراسلات المركز لتسجيل الطلب، مع توضيح أن الرسالة لا تغير الموافقة. | معالجة صدق الواجهة فقط؛ تعديل الموافقة ذاتيًا من البوابة غير منفذ. يبقى تسجيل الموافقة عبر المسار الحالي للمركز. |
| JG-27 — الاستفسار المالي | زر «استفسر عن الدفع» يفتح مراسلات الأسرة الفعلية، دون اشتراط اختيار طفل ودون ادعاء إرسال طلب اتصال. | ولي الأمر يكتب الرسالة ويرسلها؛ لم يضف دفعًا إلكترونيًا أو رفع إثبات. |
| JG-21 — يوم الأخصائي | ربط رسالة «لا توجد مواعيد متبقية» بفرع الجدول الفارغ، وفصل خطأ بدء الجلسة عنها. | لا تغيير لقواعد بدء الجلسة أو صلاحياتها. |

## التحقق

- بناء portal وops بنمط development نجح.
- بناء portal وops بنمط production نجح ضمن ميزانيات البناء الحالية.
- اختبارات portal: **63/63 ناجحة**، وتشمل الطفل الصحيح، غياب الوصول، فشل الشبكة، تبويب الملاحظات وعدم اختلاق موافقات.
- اختبارات ops: **160/160 ناجحة**، وتشمل الخطوة التالية بعد التواصل وتمرير التوقيت UTC وعدم تمرير موعد مخفي مع قرار رفض.
- `go vet ./...` و`go test ./...` نجحا في حاوية Go مؤقتة؛ اختبار جديد يرفض تاريخ تقييم بلا منطقة زمنية ويحافظ على اللحظة عند إرسال offset.
- فحص اختلافات الملفات المعدلة لم يرصد أخطاء whitespace.

لم تُطبّق هجرة ولم تُعدّل بيانات أسر أو تُرسل رسائل فعلية خلال الاختبار. تعديل الخادم يعتمد على العمود والقيد الموجودين في الهجرة 0110؛ يحتاج تشغيل النسخة المعدلة من API مع الواجهة. لم يُختبر حفظ الطلب وإرسال SMS في قاعدة تشغيل حية، ولم تُعد تشغيل الخدمات أو تُنشر التغييرات.

الأولوية التالية تبقى إكمال إسناد التقييم ونتيجته واعتماد الخطة، ثم استحقاق الباقات والدفع والأونلاين، كما في [سجل الأولويات](12-GAPS-CONFLICTS-PRIORITIES.md). لا تُعد JG-02 أو JG-13 أو JG-14 مغلقة بالكامل بهذه الإصلاحات.

## تحديث تشغيل الديف — بعد طلب المالك

تم تحديث نسخة الديف الحالية: الواجهتان تراقبان ملفات مساحة العمل والتقطتا التعديلات، وأُعيد بناء وتشغيل خدمة api وحدها باستخدام قفل التشغيل المشترك و`--no-deps`. تطابقت إعدادات بيئتها مع التكوين قبل إعادة التشغيل. نجح `go vet` والاختبارات مجددًا داخل بناء صورة الخادم.

- بوابة ولي الأمر: http://localhost:4210/login — HTTP 200.
- واجهة المركز: http://localhost:4310/login — HTTP 200.
- الخادم: healthz وreadyz على المنفذ 8090 أعادا HTTP 200، والحاوية healthy.
- مسار API عبر كل واجهة أعاد 401 لطلب غير مصادق، بما يثبت وصول الـproxy للخادم.
- قراءة السكيما أكدت وجود assessment_at. لم يُعد إنشاء قاعدة البيانات ولم تُطبّق هجرة أو تُعدّل سجلات عمل لاختبار الرحلة.

هذه إتاحة على الديف المحلية فقط؛ الاختبار المصادق للرحلة كاملة وإرسال SMS الفعلي لم يُنفذا.
