## معنى الأولوية ودرجة اليقين

P0 يمنع إكمال رحلة أساسية أو يجعل نتيجتها المالية الأساسية غير صحيحة. P1 يسبب لبسًا أو خطرًا تشغيليًا أو فقدان feedback. P2 تحسين UX يقلل جهدًا/التباسًا دون قطع المسار وحده. P3 صقل بصري. غياب ميزة مطلوبة يصنف gap لا bug regression؛ لا نتهم نسخة حية بعيب لم تُختبر. أدلة المصدر القاطعة منفصلة عن المخاطر التي تحتاج اختبارًا حيًا.

## ما الذي يحتاج تحققًا حيًا قبل تثبيت الحكم التنفيذي؟

تطبيق الهجرات على DB المتصلة، أن build المنشور يطابق هذا المصدر، memberships الحالية، تشغيل SMS/maintenance واللقاء، أحجام الموبايل وfocus، وجميع سيناريوهات [11](11-EDGE-CASES.md). وجود اختبارات قديمة أو ملفات build logs لا يثبت نجاح النسخة المفحوصة الآن. لا نغيّر الكود لإثبات المراجعة ولا ننشئ بيانات أسر حقيقية للاختبار.
