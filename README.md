# Hand By Hand — النسخة الجديدة (PostgreSQL · Go · Angular)

هذا **هو** النظام. منذ **2026-09-03** صار PostgreSQL مصدر الحقيقة الوحيد وتوقّفت
أوراكل — قرار المالك، مسجَّل بأسبابه وبما سقط من القواعد في
[`docs/01-stack-decisions.md`](docs/01-stack-decisions.md) تحت **D-26**.

> **شرطه التشغيلي:** APEX (`../hand by hand`، Oracle 21c XE + APEX 26.1) يصير للقراءة
> أو يُطفأ. نظامان يكتبان أسوأ من أيٍّ منهما وحده، وهو الخطر الذي وُضعت القاعدة ١
> أصلًا لمنعه.

## النطاق
**بوابة ولي الأمر** (`web/portal`) **وتطبيق المركز** (`web/ops`) — والثاني بديل
APP 115 في APEX، لا إضافة بجواره.

ومعهما **الموقع التعريفي العامّ** (`site/`): صفحات ثابتة بلا مصادقة ولا بيانات
شخصية، وهي **السطح الوحيد هنا المقصود أن يكون على الإنترنت المفتوح**. لا يحوي
الموقع نموذج طلب الالتحاق؛ أزراره تشير إلى `/apply` في البوّابة — مسارها الوحيد بلا
مصادقة — عبر `portalBaseUrl` في `site/config.js`. والذي يجعل نشره آمنًا بينما الـ API
ما زال يعيد رموز الدخول أنه **لا يمرّر شيئًا إلى الخدمة**: لا `proxy_pass` في
`deploy/server/site.native.mjs` ولا في كتلة nginx الخاصة به. التفاصيل في
[`site/README.md`](site/README.md).

## قواعد لا تُخرَق
1. **نظام واحد هو مصدر الحقيقة: PostgreSQL.** لا كتابة مزدوجة، ولا قاعدة بيانات ثانية
   تحمل بيانات حقيقية.
2. **قواعد العمل تُكتب في PL/pgSQL** — لا في Go ولا في Angular. الطبقة تنقل الإجابة
   ولا تقرّر، وإلا صارت نسخة ثانية من قاعدة تختلف مع الأولى يومًا ما.
3. **الحذف ناعم دائمًا.** لا منحة `DELETE` على أي جدول، وبيانات الطفل السريرية لا
   تُحذف فعليًا دون إجراء امتثال موثَّق.
4. **كل وصول — قراءة وكتابة — يمرّ عبر RLS**، والصلاحية تُفحص **داخل السياسة**.
   Go تجعل خرق ذلك أسهل، فالفحص قبل كل إصدار إلزامي.
5. **الحالات آلات حالة.** لا تحديث حرّ لعمود حالة، ولا من مدير المركز.

## الطبقات
| المجلد | ماذا يحوي |
|---|---|
| `db/` | PostgreSQL — الهجرات، دوال PL/pgSQL، سياسات RLS، البذور |
| `api/` | خدمة Go — المصادقة، الصلاحيات، الوصول للبيانات، HTTP |
| `web/` | Angular — `portal` (mobile-first) و`ops` تطبيق المركز، و`shared` للهوية البصرية |
| `site/` | الموقع التعريفي العامّ — HTML/CSS/JS خام، بلا بناء وبلا API |
| `tests/` | اختبارات القبول العابرة للطبقات — **وليست** اختبارات الوحدة |
| `deploy/` | Docker، compose، CI |
| `docs/` | ما يخص هذا الستاك فقط |
| `scripts/` | أدوات تشغيلية |

## أين تعيش الاختبارات — اقرأ هذا قبل أن تكتب أول اختبار
`tests/` **لا** تحوي اختبارات الوحدة، لأن الأداتين ترفضان ذلك:

- **Go** يوجب أن يكون `foo_test.go` في نفس حزمة `foo.go`. نقله إلى `tests/` يمنعه من
  رؤية أي شيء غير مُصدَّر، ويتحوّل الاختبار إلى اختبار واجهة عامة رغمًا عنه.
- **Angular** يضع `*.spec.ts` بجوار المكوّن بحكم إعداد الـ builder.

لذلك: **اختبار الوحدة بجوار الكود، واختبار القبول في `tests/`.**
و`tests/` هي المكافئ المباشر لسكربتات `hbh_pN_verify.sql` في المشروع الحالي —
الجزء الذي أثبت قيمته 644 مرة، وهو الذي يستحق مجلدًا مستقلًا.
