# 05 — اختبار التطبيق · المجموعة APP

**التاريخ:** 2026-09-03 · **النطاق:** التطبيقان نفسهما، مُشغَّلان في متصفّح
حقيقي **مقابل خدمة Go الحيّة وPostgreSQL الحيّة** — لا بيانات تجريبية إلا حيث
يُذكر ذلك صراحةً.

هذه ليست إعادة لمجموعات القبول. تلك تختبر الداتابيز عبر SQL والـ API عبر HTTP.
**ولا واحدة منها تشغّل التطبيق.** هذا الملف يشغّله.

## APP-OPS — تطبيق المركز، مقابل الخدمة الحيّة

مبني على `ResourceScreen` عام، ويتكلّم HTTP حقيقيًا. هذا هو التطبيق **الجاهز** فعلًا.

| # | الحالة | النتيجة |
|---|---|---|
| OPS-01 | فتح `/` بلا جلسة | ✅ تحويل إلى `/login` |
| OPS-02 | كلمة مرور خاطئة | ✅ «اسم المستخدم أو كلمة المرور غير صحيح» — **رسالة واحدة لا تفرّق بين اسم موجود وغير موجود** · حقل المرور يُفرَّغ والاسم يبقى · لا جلسة تُخزَّن |
| OPS-03 | دخول حقيقي `a4_admin` | ✅ إلى `/dashboard` · الجلسة في `sessionStorage` باسم `hbh.ops.session` |
| OPS-04 | لوحة التحكم تعرض الصلاحيات | ✅ ١٦ صلاحية، مقروءة من `/api/v1/me` لا من ثابت في العميل |
| OPS-05 | المرور على الشاشات العشر | ✅ كلّها تُعرض · **صفر خطأ في الطرفية** |
| OPS-06 | أيّها مبنيّ فعلًا | ٤ شاشات حقيقية (الأطفال · الأخصائيون · الغرف · الخدمات) و**٥ شاشات `PendingScreen`** (المواعيد · الجلسات · التقارير · الفواتير · الطلبات) — مؤجَّلة عن قصد ومكتوبة كذلك في `app.routes.ts` |
| OPS-07 | القوائم الفارغة | ✅ صادقة — الداتابيز فيها فعلًا صفر أخصائيين وصفر خدمات، والشاشة لا تخترع صفوفًا |
| OPS-08 | دخول `a4_reception` (صلاحيات أقلّ) | ✅ **٥ عناصر في القائمة بدل ١٠** |
| OPS-09 | فتح `/catalog` بالرابط مباشرةً كاستقبال | ✅ `/denied` — «لا تسمح صلاحيتك بفتح هذه الشاشة» |
| OPS-10 | **الخادم يرفض كتابة الاستقبال** — `POST /api/v1/services` | ✅ `403 FORBIDDEN` · والرفض من سياسات RLS لا من شرط في المعالِج |
| OPS-11 | لكن **قراءات** الاستقبال لنفس الموارد | ⚠️ `200` — راجع **F-09** |
| OPS-12 | سجلّ التدقيق يسجّل المحاولة المرفوضة | ✅ `DENY · a4_admin · STAFF_LOGIN BAD_CREDENTIALS` — بالاسم والوقت، كما تَعِد الشاشة |

**الحكم:** تطبيق المركز يعمل من الدخول إلى الخروج مقابل الخدمة الحقيقية.

## APP-POR — بوابة ولي الأمر، مقابل الخدمة الحيّة

المفتاح `useFixtures` في `web/shared/src/config/app-config.ts` قيمته `true` اليوم.
قُلب إلى `false` **في نسخة خاصّة خارج المستودع** — ملفّ المشروع لم يُمسّ — ثم شُغّل
التطبيق مقابل الخدمة.

| # | الحالة | النتيجة |
|---|---|---|
| POR-01 | مطابقة العقد: كل نقطة يناديها `HttpPortalApi` مقابل الخدمة | ❌ **١٣ من ١٦ ترجع `404`** — راجع **F-07** |
| POR-02 | الدخول الحقيقي برقم مسجَّل | ✅ `202` ثم `200` · الجلسة تُخزَّن · **الرقم لا يظهر في الرابط** |
| POR-03 | أول شاشة بعد الدخول تنادي `GET /me/welcome` | ❌ `404` → «تعذّر تحميل البيانات. أعد المحاولة» |
| POR-04 | ولا بطاقة طفل تُضغط، فكل شاشة داخلية ترتدّ إلى `/welcome` | ❌ **البوابة غير قابلة للاستعمال مقابل الخدمة الحقيقية** |
| POR-05 | كيف تنهار | ✅ **بهدوء** — رسالة عربية وزرّ إعادة محاولة · لا شاشة بيضاء · لا خطأ في الطرفية · لا تفاصيل خادم على الشاشة |

### وبالإعداد الذي يُشحن اليوم (`useFixtures: true`)

| # | الحالة | النتيجة |
|---|---|---|
| POR-06 | فتح `/home` بلا جلسة | ✅ تحويل إلى `/login` |
| POR-07 | مسار الدخول كاملًا | ✅ الجلسة في `sessionStorage` · الطفل في `sessionStorage` · لا بيانات شخصية في أي رابط |
| POR-08 | الشاشات التسع المحميّة | ✅ كلّها تُعرض · لا رسالة فشل · لا رمز تعبيري · لا مفتاح ترجمة خام |

## APP-RUL — قواعد المشروع، مُعاد فحصها على شجرة كبرت كثيرًا

| # | القاعدة | النتيجة |
|---|---|---|
| RUL-01 | لا رمز تعبيري في كود يُشحن | ✅ ولا ملفّ في `portal` أو `ops` أو `shared` أو `api` أو `db` |
| RUL-02 | لا نصّ عربي داخل قوالب الشاشات — كله عبر ملفّات الترجمة | ✅ ولا ملفّ، في التطبيقين |
| RUL-03 | `timestamptz` دائمًا | ✅ **صفر** عمود بلا منطقة زمنية |
| RUL-04 | كل عرض بـ `security_invoker` | ✅ **صفر** عرض بدونها |

وساعات المضيف والداتابيز والـ API والويب **متطابقة إلى الثانية** — فُحصت لأن هذا
المشروع دفع ثمن اختلاف ساعتين مرّة.
