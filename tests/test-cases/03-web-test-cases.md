## البيئة — وصفة كاملة، لأنها لم تكن موجودة

Node ليس على المضيف، و`web/portal/node_modules` مبنيّ لويندوز فـ `esbuild` يرفض
العمل داخل حاوية لينكس. لذلك: نسخة من المصدر وحده، و`npm ci` داخل الحاوية.

```bash
docker run -d --name hbh-ng -v "<copy-of-web/portal>:/app" -w /app node:22-alpine sleep infinity
docker exec hbh-ng sh -c "apk add --no-cache chromium && npm ci"
```

و`ng test` يحتاج متصفّحًا، وChromium يرفض العمل جذرًا بلا `--no-sandbox`، فيلزم
`karma.conf.js` بمشغّل مخصّص — **في بيئة الاختبار وحدها، لا في المشروع**:

```js
customLaunchers: { ChromeHeadlessNoSandbox: { base: 'ChromeHeadless',
  flags: ['--no-sandbox', '--disable-gpu', '--disable-dev-shm-usage'] } }
```

```bash
docker exec -e CHROME_BIN=/usr/bin/chromium hbh-ng \
  npx ng test --watch=false --karma-config=karma.conf.js
```

## أربعة إنذارات كاذبة من المتصفّح الصناعي

| ما بدا | ما كان |
|---|---|
| «صناديق الرمز لا تتقدّم تلقائيًا» | `type` يُدرج النصّ دفعةً واحدة (`insertText`)، و`maxlength="1"` يبقي حرفًا ويُطلق `input` مرّة واحدة |
| «الضغط على الأرقام لا يفعل شيئًا» | الصندوق كان ممتلئًا سلفًا من المحاولة قبلها؛ `maxlength` يمنع، فلا `input` ولا تقدّم |
| «`Backspace` لا يمسح» | الحالة في الإشارة تُعيد كتابة قيمة الصندوق، وأحداث المفاتيح الصناعية لم تصل المعالِج |
| «التنقّل لا يعمل على ستّ شاشات» | `pushState` + `popstate` ليس سائقًا موثوقًا لموجّه Angular؛ الشاشات تعمل بالنقر وبالتحميل المباشر |

**ولا واحد منها عيب.** حين شُغّل المسار بـ `form_input` — الذي يُطلق أحداث الإدخال
الحقيقية — تقدّمت الصناديق، وسُلّم النموذج تلقائيًا عند الرقم السادس، ودخلت الجلسة.

وهذا هو الدرس: **أداة اختبار تكذب مثل أي شيء آخر، وفرقٌ بين «لم يعمل» و«لم أشغّله
كما يشتغل».** تسجيل الأربعة هنا أرخص من أن يعيد أحدهم اكتشافها.
