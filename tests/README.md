# tests — اختبارات القبول

هذا المجلد هو المكافئ المباشر لسكربتات `hbh_pN_verify.sql`: الجزء الذي أثبت قيمته
644 مرة في المشروع الحالي، وكشف عيوبًا لم يكن أي منها ليظهر قبل الإنتاج.

| مجلد | ما يخصه |
|---|---|
| `db/` | قواعد على مستوى قاعدة البيانات: القيود، المشغّلات، **سياسات RLS** |
| `api/` | تكامل يمسّ قاعدة بيانات حقيقية |
| `e2e/` | من المتصفح: دخول بـ OTP، عرض جدول الطفل |
| `fixtures/` | مركز صغير قابل لإعادة البناء |

**اختبارات الوحدة ليست هنا** — راجع README الجذر للسبب.

## أربع قواعد اشتُريت بأثمانها في المشروع الحالي
1. **أكّد رمز الخطأ نفسه، لا مجرد وقوع فشل.** اختبار ينتظر رفضًا فيأتيه رفض لسبب آخر
   لم يثبت شيئًا — ويبدو أخضر. حدث هذا مرتين في مرحلة واحدة.
2. **تحقّق من التجهيزة قبل الاختبارات، لا من خلالها.** ثلاث مراحل متتالية خسرت دورة
   كاملة بسبب قطعة منسيّة في التجهيزة ظهرت لاحقًا كرفض محيّر من كود سليم.
   كل مجموعة تنتهي تجهيزتها بكتلة تؤكّد كل شرط مسبق **بالاسم**.
3. **قاعدة الفرادة تحتاج صفّين على نفس جانب القاعدة، لا واحدًا من كل جانب.**
   فهرس فريد مركّب نجا من 73 اختبارًا لأن المجموعة أنشأت طفلًا برقم قومي وآخر بدونه،
   وهما لا يتصادمان أبدًا. كان سيرفض ثاني طفل بلا رقم قومي في أول يوم استقبال.
4. **تنظيف يبتلع فشله أسوأ من غياب التنظيف.** كل مسار خطأ يطبع سببه قبل التراجع،
   وإلا "نجح" التنظيف وقتل التشغيلة التالية بسبب لا علاقة له بالحقيقي.

## وقاعدة خامسة، من نفس المصدر
**سكربت تحقّق يموت قبل حكمه يُقرأ كنجاح.** الحكم النهائي هو الغاية، ولا يجوز
أن يتخطّاه شيء. كل فحص يمسّ سلوكًا حيًّا يُعزَل حتى لا يُسقِط المجموعة قبل حكمها.
